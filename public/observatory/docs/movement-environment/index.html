Movement and environment

The diving experience combines authoritative swim state and oxygen with client-side physics, animation, cameras, equipment, and underwater rendering.

Swimming​

SwimmingService owns server character setup and the Swim remote contract. SwimmingController owns responsive local movement:

  • camera-relative horizontal movement,
  • ascent and descent input,
  • buoyancy and drag,
  • physics constraints and orientation,
  • directional swimming animations,
  • character IK,
  • equipped DPV speed modifiers,
  • gamepad and mobile input,
  • character lifecycle cleanup.

The client computes responsive forces, while the server controls which characters may enter or leave the swimming state.

Oxygen​

OxygenService attaches authoritative oxygen state to characters and sends OxygenEvents.OxygenSync updates. It disables conflicting default health scripts where required and applies depletion or recovery based on the character's environment.

OxygenBalance renders the player's oxygen. DepthAtmosphereController consumes the same state to coordinate environmental presentation.

Do not let a UI bar or local attribute become the authoritative oxygen value.

Vehicles and equipment​

DPVService validates and configures double-DPV state on the server. DoubleDPV handles client animation, motor presentation, and registration. ScooterService and the Scooter component provide the corresponding single-vehicle contract.

Gear visibility is split between authoritative attachment behavior and a player setting synchronized through GearVisibilityEvents.

Character cleanup​

Movement systems attach constraints, IK controls, animation tracks, input bindings, render callbacks, and tool listeners. Cleanup must run on:

  • character removal,
  • humanoid death,
  • swimming disable,
  • tool unequip,
  • controller destruction,
  • teleport or state replacement.

Repeated character spawns are the primary leak test for this subsystem.

Cross-device testing​

Test keyboard and mouse, gamepad, touch controls, VR, and mobile emulation. Verify simultaneous directional and vertical input, camera-relative movement, DPV transitions, oxygen depletion, and the absence of orphaned mobile buttons.
