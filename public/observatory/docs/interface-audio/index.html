Interface and audio

Aquatica's interface layer combines reusable UI construction modules, screen-specific components, an interface navigation handler, notices, and one central audio configuration.

UI layers​

LayerExamples
FoundationUIFactory, UIColors, InterfaceHandler, buttons, sliders, card stacks, push/pop
Screen componentsStore, achievements, encyclopedia, settings, tip jar, elevator, jukebox
HUD componentsCurrency, health, oxygen, directional markers, notifications
ControllersUserInterface, StoreController, TopbarManager, TooltipController
World displaysGlobalEventDisplay, exhibit UI, popups, markers

Premade StarterGui templates should own stable layout and script-facing names. Runtime modules populate content, clone small templates, and bind behavior.

Navigation​

InterfaceHandler coordinates screen configuration, visibility transitions, button behavior, and stacked navigation. Screens should close through the handler rather than mutating unrelated GUI visibility directly.

Camera-owning screens must coordinate with CameraControlManager and release ownership on every close path.

Notifications​

There are two presentation paths:

  • notices for general server messages,
  • typed notification cards for information, success, warning, and error.

The ShowNotifications player setting must be respected without preventing the underlying gameplay result.

Audio authority​

Runtime.Config.Shared.Sounds is the only first-party location for sound asset IDs. It contains:

  • UI interaction and notification IDs,
  • ambience,
  • area playlists,
  • intro, open-ocean, and merchant music,
  • gameplay SFX,
  • material footsteps,
  • sound groups and SoundHandler source definitions.

SoundHandler owns source creation, one-shots, positioned playback, loops, stack arbitration, group volume, and music overrides. UIAudio is a playback adapter and contains no IDs.

warning

Do not add an asset ID to a controller, component, or UI module. Add it to the shared sound config and reference the named entry.

Area music​

AreaController consumes Sounds.Areas, builds Sound objects, and responds to the player's tagged area. Area settings define volume, fade time, crossfade, order, looping, and priority.

Merchant playback uses a separate sound group so it can remain audible while the normal music group is ducked.

UI quality checklist​

  • Semantic instance names and stable lookup paths.
  • Templates hidden or detached during runtime.
  • Input parity for mouse, touch, gamepad, and VR.
  • No connections or camera state left behind after close.
  • Sound volume routed through the correct group.
  • Hover and click feedback do not fire for disabled controls.
  • Notification dots expose explicit enabled state and stop pulsing when clear.
