Engineering Aquatica Observatory

Aquatica Observatory is a persistent Roblox experience where players explore a marine facility and surrounding ocean, scan wildlife, complete discoveries, collect environmental rewards, and customize their diving loadout.

The codebase is organized as a game runtime rather than a collection of independent scripts. Mince discovers modules, applies shared configuration, coordinates lifecycle phases, mounts tagged components, and exposes the remote and ByteNet communication layers used by the rest of the game.

Read by ownership

When changing a feature, begin with the server authority, then follow its client controller, shared configuration, packets or remotes, and UI consumer. The module map lists those relationships.

Source boundaries​

  • ServerScriptService/Runtime owns authoritative data and gameplay decisions.
  • ReplicatedStorage/Runtime owns shared configuration and client runtime code.
  • ReplicatedStorage/Modules contains Mince, networking schemas, UI modules, simulation libraries, and reusable utilities.
  • ReplicatedStorage/Assets contains discoverable species definitions and runtime assets.
  • ServerStorage/Runtime contains the separate LightRunner boot path and server-only implementation assets.

Third-party packages and Roblox's default player modules are dependencies, not first-party extension points. Avoid editing them unless the dependency itself is intentionally being forked.

Engineering rules​

  • The server owns profile data, currency, entitlements, rewards, and grants.
  • Client requests must be validated against server configuration and state.
  • A tagged component must clean up every connection, animation track, and transient instance it creates.
  • ByteNet packet schemas live in replicated modules and are shared verbatim by both sides.
  • Sound asset IDs belong only in the shared sound configuration.
  • Run StyLua and Selene on touched Luau, then build Moonwave before publishing.
