Development workflow

Aquatica is edited locally and synchronized with the live Roblox Studio place through Abraxius.

Inspect, edit, validate, sync​

Inspect live Studio path
        |
        v
Pull the exact script
        |
        v
Edit mapped local source
        |
        v
StyLua + Selene + relevant tests
        |
        v
Push that file once
        |
        v
Confirm Abraxius status is live

Do not retry a push reported as pending. Abraxius tracks it until Studio confirms the source.

Local commands​

npm run format
npm run quality
npm run docs:build
npm run docs:serve

The repository contains legacy and vendored source with existing warnings. During focused changes, run StyLua and Selene on every touched first-party file and report unrelated baseline failures separately.

Documentation standards​

  • Write task-oriented pages with ownership and data flow.
  • Use exact module names and stable identifiers.
  • Explain server authority and cleanup requirements.
  • Prefer diagrams and tables only where they clarify relationships.
  • Link related systems instead of duplicating long explanations.
  • Run Moonwave with broken-link checking set to throw.

Publishing​

Moonwave builds the static site with a base path of /observatory/. The portfolio repository copies the generated site under public/observatory, and its Vite GitHub Pages build publishes that folder unchanged.

Observatory docs + selected source annotations
        |
        v
moonwave build
        |
        v
portfolio/public/observatory
        |
        v
npm run build:pages
        |
        v
velumix.github.io/observatory/

Change checklist​

  • Inspect the live implementation before documenting behavior.
  • Keep private credentials, secrets, and operational endpoints out of public documentation.
  • Update the module map when ownership moves.
  • Update saved-data docs when schema changes.
  • Update networking docs when a remote or packet contract changes.
  • Verify the published subpath locally before pushing the website.
